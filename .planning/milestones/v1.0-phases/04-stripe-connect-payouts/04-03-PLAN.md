3. For each marina card, add Stripe Connect status display:

   **When NOT connected (no stripe_account_id OR payouts_enabled is false):**
   - Show a prominent banner/card ABOVE the marina grid (or within each marina card) with:
     - Yellow/amber background
     - Text: "Complete Stripe setup to start receiving bookings"
     - "Connect Stripe" button (teal, same style as "Add Marina" button)
   - On click: POST to /api/connect/onboard with { marinaId }, then window.location.href = response.url (redirect to Stripe hosted onboarding)
   - Show loading state on button during API call

   **When connected (payouts_enabled is true):**
   - Green checkmark badge next to marina name (use a simple green dot + "Stripe Connected" text, or a green StatusBadge)
   - "View Payouts" button (outlined style, not primary)
   - On click: POST to /api/connect/login-link with { marinaId }, then window.open(response.url, '_blank') (opens Stripe Express Dashboard in new tab)

   **When onboarding started but not complete (stripe_account_id exists, payouts_enabled is false):**
   - Same banner as "not connected" but text: "Complete Stripe setup to start receiving bookings"
   - "Continue Setup" button instead of "Connect Stripe" — calls same onboard endpoint (which detects existing account and generates new link)

4. Handle stripeStatus query param from return URL:
   - If URL has ?stripeStatus=connected, show a brief success toast or green banner: "Stripe account connected successfully!"
   - If ?stripeStatus=pending, show info banner: "Stripe setup is pending. We'll update your status automatically."
   - Clear the query param after displaying (use router.replace to remove it from URL)

Use existing Tailwind classes consistent with the dashboard design. The Connect card should be visually distinct (amber/yellow for action needed, green for connected).

  <action>
1. Create `src/app/api/connect/login-link/route.ts` — POST handler:
   - Authenticate user via createClient().auth.getUser() — return 401 if not authenticated
   - Accept { marinaId } from request body
   - Verify user owns this marina (query with owner_id = user.id)
   - Fetch marina's stripe_account_id and payouts_enabled
   - If no stripe_account_id or payouts_enabled is false, return 400 with error "Stripe account not fully connected"
   - Generate login link: stripe.accounts.createLoginLink(marina.stripe_account_id)
   - Return { url: loginLink.url }
   - Use same patterns as other Connect routes: getStripe(), createAdminClient(), try-catch

2. Extend `src/app/api/webhooks/stripe/route.ts` — add account.updated case:
   - Add new case in the existing switch statement: 'account.updated'
   - Extract account from event.data.object (as Stripe.Account)
   - Get connected account ID: use event.account property if available (Connect webhook events include this), otherwise fall back to account.id
   - Update marinas table via adminClient: SET stripe_onboarding_complete = account.details_submitted, payouts_enabled = account.payouts_enabled WHERE stripe_account_id = connectedAccountId
   - If DB update fails, return 500 (Stripe retries)
   - Record in stripe_processed_events with booking_id: null (this is not a booking event)
   - Follow existing error handling pattern: console.error on failure, 500 response for Stripe retry

Note on webhook secret: Use the same STRIPE_WEBHOOK_SECRET. The endpoint must be configured in Stripe Dashboard for "Events on Connected accounts" to receive account.updated events. This is a dashboard configuration step, not a code change. Document this in the summary.
