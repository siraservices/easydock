    - Test: deny route updates booking status to 'declined' and returns success

    Create POST /api/bookings/[id]/approve/route.ts:

    2. Get user via supabase.auth.getUser() — return 401 if not authenticated
    3. Use the USER client (not adminClient) to update booking status to 'approved' where id matches — RLS on bookings table already scopes UPDATE to marina owners who own the marina. This means if the user is not the marina owner, the update returns no rows.

    5. If no data returned, return 404 { error: 'Not found or not authorized' }
    6. Return 200 { success: true, booking: data }

    Create POST /api/bookings/[id]/deny/route.ts — same pattern but status = 'declined' (not 'denied' — the DB enum uses 'declined').

    Create test files following the mockState pattern from existing tests (see src/__tests__/webhook-idempotency.test.ts for the mock pattern). Mock supabase.auth.getUser and supabase.from('bookings').update.

    Note on params: In Next.js 15 App Router, the second argument to route handlers is `{ params }` where params is a Promise. Use `const { id } = await params` to extract the booking ID.
