<task type="auto">
  <name>Task 2: Rewrite webhook handler with idempotency and error-aware responses</name>
  <files>src/app/api/webhooks/stripe/route.ts</files>
  <action>
Rewrite `src/app/api/webhooks/stripe/route.ts` with the following logic:

1. **Signature verification** (same as current):
   ```typescript
   const body = await request.text();
   const signature = request.headers.get("stripe-signature");
   if (!signature) return NextResponse.json({ error: "Missing signature" }, { status: 400 });
   const event = stripe.webhooks.constructEvent(body, signature, webhookSecret);
   ```
   Return 400 on invalid signature (Stripe will not retry bad signatures).

2. **Idempotency check** — before any processing:
   ```typescript
   const supabase = createAdminClient();
   const { data: existing } = await supabase
     .from('stripe_processed_events')
     .select('id')
     .eq('id', event.id)
     .single();

   if (existing) {
     return NextResponse.json({ received: true }); // 200 — already processed
   }
   ```

3. **Event processing with error-aware responses:**

   **`checkout.session.completed`:**
   - Extract `bookingId` from `session.metadata.booking_id` and `paymentIntentId` from `session.payment_intent`
   - If no bookingId: log warning, record event, return 200 (nothing to process)
   - Update booking: `adminClient.from('bookings').update({ status: 'confirmed', stripe_payment_intent_id: paymentIntentId }).eq('id', bookingId)`
   - If DB write error:
     - Attempt auto-refund: `stripe.refunds.create({ payment_intent: paymentIntentId })`
     - Wrap refund in try/catch — log refund errors but do NOT insert into stripe_processed_events
     - Return 500 (Stripe retries; idempotency check will prevent double-processing if DB is back up on retry)
   - On success: insert into `stripe_processed_events` with `{ id: event.id, event_type: event.type, booking_id: bookingId }`

   **`checkout.session.expired`:**
   - Extract bookingId from metadata
   - Update booking status to 'cancelled'
   - If DB write error: return 500 (Stripe retries)
   - On success: insert into stripe_processed_events, return 200

   **Default (unhandled event types):**
   - Return 200 (acknowledge receipt, no processing needed)

4. **HTTP status semantics:**
   - `400` — Invalid/missing signature
   - `200` — Success OR already processed OR unhandled event type
   - `500` — DB write failed (Stripe retries with exponential backoff)

After completing the rewrite, run tests again and fix any failures. The webhook tests from Task 1 should now pass GREEN.
