Modify `src/app/api/checkout/route.ts` to add Stripe Connect destination charge support:

1. After the existing slip fetch (line ~57) and before creating the Stripe session, add a Connect status guard:
   - Query marina's stripe_account_id and payouts_enabled using adminClient (not the user client — these fields may not be visible via RLS)
   - If marina has no stripe_account_id OR payouts_enabled is false, return 422 with error: "This marina is not currently accepting online payments. Please try another marina."
   - This check uses the marinaId already available from the request body

2. Modify the stripe.checkout.sessions.create() call to add payment_intent_data:
   ```
   payment_intent_data: {
     application_fee_amount: Math.round(platformFeeAmount * 100),
     transfer_data: {
       destination: marina.stripe_account_id,
     },
   },
   ```
   CRITICAL: application_fee_amount is in CENTS. platformFeeAmount is in dollars. Must multiply by 100 and Math.round().
   CRITICAL: These fields go under payment_intent_data, NOT at session top level.

3. Add a safety guard: application_fee_amount must not exceed total charge amount.
   ```
   const applicationFeeCents = Math.round(platformFeeAmount * 100);
   const totalChargeCents = Math.round(totalChargedToCustomer * 100);
   const safeFee = Math.min(applicationFeeCents, totalChargeCents - 1);
   ```

Do NOT change the line_items, fee calculation, or booking creation logic. Only add the Connect guard and payment_intent_data.
