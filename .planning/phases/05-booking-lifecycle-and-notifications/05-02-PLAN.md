    - Test: cancel route returns 409 if booking is already cancelled
    - Test: cancel route updates DB status to 'cancelled' before calling Stripe
    - Test: cancel route calls stripe.refunds.create with reverse_transfer=true and refund_application_fee=true when stripe_payment_intent_id exists
    - Test: cancel route succeeds even if no stripe_payment_intent_id (booking was never paid)
    - Test: cancel route returns 200 with { success: true, refunded: true/false }
  </behavior>
  <action>
    Create POST /api/bookings/[id]/cancel/route.ts:

    1. Import createClient from @/lib/supabase/server, createAdminClient from @/lib/supabase/admin, Stripe from 'stripe'
    2. Authenticate via supabase.auth.getUser() — return 401 if no user
    3. Use adminClient to fetch the booking by ID (boat owners have no SELECT restriction issues, but adminClient ensures consistent access): .select('*, marinas(owner_id)').eq('id', id).single()
    4. Return 404 if not found
    5. Authorization check: user.id must equal booking.boat_owner_id OR booking.marinas.owner_id. Return 403 if neither.
    6. Check-in guard: if new Date(booking.check_in) <= new Date() (comparing date strings — use startOfDay comparison to handle timezone: compare YYYY-MM-DD strings directly since check_in is stored as date), return 422 { error: 'Cannot cancel after check-in date' }
    7. Already-cancelled guard: if booking.status === 'cancelled', return 409 { error: 'Booking is already cancelled' }
    8. DB-first update: adminClient.from('bookings').update({ status: 'cancelled' }).eq('id', id).eq('status', booking.status) — the .eq('status', booking.status) is an optimistic lock preventing race conditions. If 0 rows affected, return 409.
    9. Stripe refund (only if stripe_payment_intent_id exists):
       ```typescript
       const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!);
       await stripe.refunds.create({
         payment_intent: booking.stripe_payment_intent_id,
         reverse_transfer: true,
         refund_application_fee: true,
       });
       ```
    10. Return 200 { success: true, refunded: !!booking.stripe_payment_intent_id }

    Note on params: In Next.js 15, use `const { id } = await params` (params is a Promise).

    For the check-in date comparison, compare the booking.check_in string (YYYY-MM-DD) against today's date formatted as YYYY-MM-DD in the server's timezone. This avoids UTC midnight edge cases:
    ```typescript
    const today = new Date().toISOString().split('T')[0]; // YYYY-MM-DD
    if (booking.check_in <= today) { return 422 }
    ```

    Create test file following existing mock patterns. Mock Stripe with vi.mock('stripe') and verify refunds.create is called with the correct parameters.
