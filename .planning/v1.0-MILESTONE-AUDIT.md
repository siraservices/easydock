### Phase 3 Gap Detail

`buildSlipQuery` in `src/lib/hooks/use-map-filter.ts` is missing two `.not()` guards for null marina coordinates. The test expects them but the implementation omits them. Client-side `filterMarinasByViewport` already handles null coordinates, so there is no functional regression — purely a query correctness and test alignment issue. **Fix:** Add two lines to `buildSlipQuery`.

### Integration Issues (Non-Blocking)

1. **Mock data blocks demo path** — Mock marinas have no Stripe Connect account. Checkout returns 422 when booking mock slips. No production impact (real marinas will have real Connect accounts).

2. **Dead client-side price calculation** — `booking-widget.tsx` computes and sends `totalPrice` that the server silently ignores. Display price could diverge from charged price if rate changes between page load and submission.

3. **Misleading migration filename** — `database/006_marina_leads.sql` actually creates `marina_prospects` table. No runtime impact.
